= Connect to Savanna with pyTigerGraph

You can use pyTigerGraph to connect a Python application to a TigerGraph database in Savanna and work with graph data through the pyTigerGraph SDK.

Savanna uses a Database Secret passed directly into the connection, rather than the username/password flow described in xref:pytigergraph:getting-started:connection.adoc[Connecting to TigerGraph]. Use this page if your database runs on Savanna.

== Before you begin

Before you connect to your database, make sure you have the following:

* A running Savanna workspace with an attached database.
* The Savanna workspace URL.
* The name of the graph you want to access.
* A Database Secret with the required permissions, generated for that
specific graph (see note below).

== Install pyTigerGraph

Install pyTigerGraph in your Python environment:

[source,bash]
----
pip install pyTigerGraph
----

Verify the install:

[source,bash]
----
python -c "import pyTigerGraph; print(pyTigerGraph.__version__)"
----

For more information, see
xref:pytigergraph:getting-started:install.adoc[Install pyTigerGraph].

== Get the connection information

You need the following values from your Savanna workspace to create a
pyTigerGraph connection:

[cols="1,2,2", options="header"]
|===
|Value |Purpose |Source

|Workspace URL
|Host used to reach the Savanna database.
|Savanna workspace General tab

|Graph name
|Graph that the application will access.
|Savanna Design Schema page

|Database Secret
|Credential used to obtain an authentication token.
|Savanna Database Secrets
|===

=== Get the workspace URL

Open your Savanna workspace and copy the workspace URL. It must include the
`https://` scheme when used as the pyTigerGraph host.

For more information, see
xref:workgroup-workspace:workspaces/how2-create-a-workspace.adoc[Set up a Savanna workspace].

=== Get the graph name

Identify the graph associated with the database you want your application to
access. Use the exact graph name, including capitalization, when creating the
connection.

=== Create a Database Secret

Create or obtain a Database Secret in Savanna.

[IMPORTANT]
====
Make sure the Database Secret you use has access to the same graph specified
in `graphname`. A mismatch can result in an authentication failure.
====

For more information, see
xref:administration:settings/how2-create-database-secret.adoc[Manage Database Secrets].
[NOTE]
====
Keep your Database Secret secure. Do not commit it to source control or
expose it in application logs.
====

== Create a connection

[source,python]
----
import pyTigerGraph as tg

HOST = "https://<your-savanna-workspace-url>"
GRAPH = "<your-graph-name>"
SECRET = "<your-database-secret>"

conn = tg.TigerGraphConnection(
    host=HOST,
    graphname=GRAPH,
    gsqlSecret=SECRET
)
----

[NOTE]
====
Pass the Database Secret directly to the constructor via `gsqlSecret`.
Calling `getToken()` alone, without also setting `gsqlSecret` here, is a
common cause of `User authentication failed` errors on Savanna.
====

For more information, see
xref:pytigergraph:getting-started:connection.adoc[Connect to TigerGraph].

== Authenticate

Use the Database Secret to request an authentication token for the
connection:

[source,python]
----
conn.getToken(SECRET)
----

The token is stored in the connection object and is used for subsequent
authenticated requests.

For more information, see
xref:pytigergraph:core-functions:auth.adoc[Authenticate with TigerGraph].

== Verify the connection

[source,python]
----
print("Vertex types:", conn.getVertexTypes())
print("Edge types:", conn.getEdgeTypes())
----

If this returns the vertex and edge types defined in your graph, the
connection and authentication flow are working.

== Troubleshoot connection issues

`Invalid URL scheme` error::
The workspace URL is missing `https://`. Copy it exactly as shown in the
Savanna console.

`User authentication failed` error::
Check these in order:

. Was the Database Secret generated for the *same graph* named in `graphname`?
A secret from a different graph in the same workspace fails with this
identical error, with no indication of the mismatch.
. Is the secret passed to `gsqlSecret` in the constructor (not only to
`getToken()`)? See <<_create_a_connection,Create a connection>>.
. Generate a new Database Secret if the existing one may have been
revoked.

For additional authentication information, see
xref:pytigergraph:core-functions:auth.adoc[Authentication Functions].
