= Savanna REST API (previous overview)
:experimental:

// This is a previous draft of the REST API overview, kept temporarily for side-by-side comparison with xref:savanna:rest-api:index.adoc[the current overview].

The Savanna REST API is the control plane for TigerGraph Savanna. Use it to provision and manage the resources behind your graphs, such as cloud providers, workgroups, workspaces, add-ons, backups, networking, and organization users, from your own scripts, services, and CI/CD pipelines instead of the Savanna UI.

Everything in this reference runs against a single base URL and authenticates with an API key, so you can automate the full lifecycle of a workspace: create it, size it, protect it with backups, schedule it to save cost, and tear it down when you are done.

== Control plane vs. data plane

Savanna exposes two different APIs. Knowing which one you need saves time.

[options="header",cols="1a,3a,3a"]
|===
|API |What it manages |Where it lives

|*Control plane* (this reference)
|The resources _around_ your graph: cloud providers, workgroups, workspaces, databases, add-ons, backups, IP allow lists, schedules, and org users.
|`https://api.tgcloud.io/controller/v4/v2`

|*Data plane* (REST{plus}{plus})
|The data _inside_ a workspace: schema, loading jobs, GSQL queries, and results.
|Your workspace host, for example `https://<workspace-id>.i.tgcloud.io`
|===

For data-plane calls against a running workspace, see xref:savanna:workgroup-workspace:workspaces/connect-via-api.adoc[Connect via APIs]. To drive Savanna with an AI agent in natural language, see xref:savanna:get-started:connect-agent-mcp.adoc[Connect AI tools with MCP].

== The resource model

Control-plane resources are nested. Most paths follow this hierarchy, so understanding it makes the endpoints predictable.

[options="header",cols="1a,4a"]
|===
|Resource |What it is

|*Organization*
|Your Savanna account boundary. Owns users, roles, quotas, add-ons, and cloud providers.

|*Cloud provider*
|Where a workgroup deploys: a TigerGraph-operated region, or a Bring Your Own Cloud (BYOC) account you register.

|*Workgroup*
|A container that groups related workspaces and holds shared settings such as the IP allow list. Lives in a cloud provider and region.

|*Workspace*
|A running, independently scalable compute environment attached to a *database*. This is what you connect to, query, back up, pause, and schedule.

|*Database*
|The persistent storage for a workspace's graph data. Created with the workspace; managed within its workgroup.
|===

A typical path reflects that nesting:

[source]
----
/controller/v4/v2/workgroups/{workgroupID}/workspaces/{workspaceID}/backups
----

== Base URL

All control-plane endpoints are relative to:

[source]
----
https://api.tgcloud.io/controller/v4/v2
----

Requests and responses use `application/json`.

== Authentication

Authenticate every control-plane request with an API key passed in the `x-api-key` header.

[source,bash]
----
curl -X GET "https://api.tgcloud.io/controller/v4/v2/workgroups" \
  -H "Content-Type: application/json" \
  -H "x-api-key: <your-api-key>"
----

Savanna uses different credentials for different layers. Pick the one that matches the call you are making.

[options="header",cols="2a,2a,3a,3a"]
|===
|Credential |Sent as |Use it for |Where to get it

|*Control-plane API key*
|`x-api-key` header
|Every endpoint in this reference (workgroups, workspaces, backups, org).
|xref:savanna:rest-api:create-api-key.adoc[Create an API key]

|*Database secret*
|Bearer token on the workspace host
|Data-plane REST{plus}{plus} queries against a running workspace.
|xref:savanna:administration:settings/how2-create-database-secret.adoc[Create a database secret]

|*In-database GSQL user*
|Managed through this API, used by the graph engine
|GSQL and role-based access _inside_ a workspace.
|<<indb-users,Manage in-database users>> (below)
|===

[TIP]
====
Keep API keys out of source control. Store them as environment variables or in a secrets manager, and rotate them from the Savanna console.
====

== Get started

Provision your first workspace end to end, then connect to it on the data plane.

. xref:savanna:rest-api:create-api-key.adoc[Create an API key] and export it as `x-api-key`.
. Call xref:savanna:rest-api:endpoints/get-supported-workspace-options.adoc[Get supported workspace options] to see the regions and workspace types available to you.
. xref:savanna:rest-api:endpoints/create-a-workgroup.adoc[Create a workgroup] in your chosen region.
. xref:savanna:rest-api:endpoints/create-a-workspace.adoc[Create a workspace] in that workgroup.
. Poll xref:savanna:rest-api:endpoints/get-workspace-details.adoc[Get workspace details] until its status is ready.
. xref:savanna:workgroup-workspace:workspaces/connect-via-api.adoc[Connect via APIs] to load data and run GSQL on the data plane.
